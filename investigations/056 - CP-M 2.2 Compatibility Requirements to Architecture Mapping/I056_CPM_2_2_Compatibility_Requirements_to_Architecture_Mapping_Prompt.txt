OBJECTIVE

Determine how the established CP/M 2.2 compatibility contract maps to
architectural responsibilities.

Previous investigations established:

- documented CP/M behavior;
- Digital Research implementation behavior;
- software ecosystem compatibility requirements;
- regression validation requirements;
- practical CP/M community compatibility standard.

Investigation 056 determines which BetterCP/M architectural boundaries
must be responsible for satisfying those compatibility requirements.

Determine:

- which compatibility requirements require dedicated architectural
  support;
- which requirements can be isolated within compatibility layers;
- which requirements are implementation choices rather than
  compatibility requirements.


COMPATIBILITY STANDARD

Consider:

- documented CP/M 2.2 behavior;
- Digital Research implementation behavior;
- common CP/M programming practices;
- historically significant software dependencies.

The objective is to map requirements to responsibilities.

Do not design the BetterCP/M architecture itself.

INVESTIGATION QUESTIONS


1. REQUIREMENT OWNERSHIP

Determine:

- which subsystem must satisfy each compatibility requirement;
- whether requirements belong to CCP, BDOS, BIOS, storage, runtime, or
  another boundary.


2. COMPATIBILITY BOUNDARIES

Determine:

- which behaviors must be preserved directly;
- which behaviors may be provided through abstraction layers;
- which behaviors may vary without affecting compatibility.


3. LAYER RESPONSIBILITY

Determine:

- where compatibility responsibilities logically belong;
- where interfaces between responsibilities exist;
- where responsibility boundaries remain unclear.


4. VALIDATION MAPPING

Determine:

- which regression tests validate each responsibility;
- which evidence supports each mapping.


5. IMPLEMENTATION INDEPENDENCE

Determine:

- which requirements are architectural constraints;
- which requirements permit implementation flexibility.


6. REMAINING QUESTIONS

Identify:

- unresolved architectural implications;
- requirements requiring further investigation;
- compatibility questions not yet assigned ownership.


7. EXPERIMENTAL REQUIREMENTS

Create requirement-to-responsibility mappings.

Each mapping must include:

- compatibility requirement;
- evidence source;
- responsible boundary;
- validation method;
- classification.
