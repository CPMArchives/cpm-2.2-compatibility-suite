OBJECTIVE

Define the CP/M 2.2 BDOS directory search contract.

Previous investigations established:

- FCB construction and default FCBs;
- file operation semantics;
- failure behavior;
- DMA behavior;
- BDOS calling conventions.

Investigation 029 determines the complete application-visible contract
for:

- Search First;
- Search Next;
- directory entry matching;
- wildcard interpretation;
- DMA result placement;
- multi-entry enumeration;
- interaction with user areas and drives.

The goal is to determine what a CP/M application may rely upon when
enumerating directory entries.

KEY QUESTIONS


1. SEARCH FIRST ENTRY CONDITIONS

Determine:

- required FCB contents;
- wildcard behavior;
- drive byte interpretation;
- user area selection;
- current drive interaction.


2. SEARCH NEXT STATE

Determine:

- where search state is maintained;
- whether Search Next depends on unchanged FCB contents;
- whether unrelated BDOS calls invalidate search state;
- whether changing drives/users affects enumeration.


3. DIRECTORY MATCHING

Determine:

- filename matching rules;
- extension matching;
- wildcard behavior;
- lowercase/uppercase handling;
- special directory entries.


4. DMA RESULT FORMAT

Determine:

- exact DMA contents after a successful search;
- directory entry offset;
- returned entry format;
- extent information;
- allocation information.

Cross-check I017.


5. MULTIPLE MATCHES

Determine:

- return values;
- order of returned entries;
- duplicate extent behavior;
- whether all matching extents are returned.


6. FAILURE CONDITIONS

Determine:

- no match;
- invalid drive;
- invalid FCB;
- end of search;
- unavailable media.

Separate:

returned failure

from:

fatal DRI behavior.


7. USER AREA BEHAVIOR

Determine:

- whether searches include only current user;
- explicit user selection behavior;
- interaction with user 0/public files if applicable.


8. DRIVE BEHAVIOR

Determine:

- FCB drive prefix;
- current drive;
- invalid drives;
- drive changes during search.


9. SEARCH STATE LIFETIME

Determine whether search state survives:

- another BDOS call;
- disk selection;
- DMA changes;
- termination;
- warm boot.


10. DRI SOURCE ANALYSIS

Review BDOS source for:

- search initialization;
- directory scanning;
- matching routines;
- DMA construction;
- return paths.

Extract compatibility-relevant behavior only.

FINAL GOAL

Define the CP/M 2.2 directory enumeration contract:

When a CP/M application asks BDOS to search for files,
what matching rules apply,
what information is returned,
how does enumeration continue,
and what behavior must a compatible implementation provide?

The result should establish Search First/Search Next as a stable
application-facing compatibility boundary without requiring reproduction
of DRI-private directory scanning implementation details.
