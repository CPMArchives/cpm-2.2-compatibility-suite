Create Investigation 067 as a new evidence report with its own directory

OBJECTIVE

Validate hardware compatibility profiles to determine the boundary
between generic CP/M 2.2 compatibility and machine-specific behavior.

Previous investigations established:

- the CP/M 2.2 compatibility standard;
- hardware-dependent software boundaries;
- processor and instruction assumptions;
- communications profiles;
- storage fault behavior;
- conformance requirements.

Investigation 067 determines whether hardware-specific compatibility
claims can be defined and validated separately from the general CP/M
compatibility contract.

Determine:

- which hardware behaviors belong to compatibility profiles;
- which behaviors remain outside the CP/M contract;
- what evidence is required to claim compatibility with a specific
  hardware environment.


COMPATIBILITY STANDARD

Consider:

- documented CP/M 2.2 behavior;
- Digital Research implementation behavior;
- common CP/M programming practices;
- historically significant hardware dependencies.

Distinguish between:

- generic CP/M compatibility;
- BIOS-level compatibility;
- machine-profile compatibility;
- implementation-specific behavior.

Do not assume a hardware feature is required without evidence.

INVESTIGATION QUESTIONS


1. HARDWARE PROFILE CORPUS

Identify representative CP/M hardware environments.

Record:

- hardware name;
- processor;
- BIOS characteristics;
- storage devices;
- peripherals;
- software dependencies;
- evidence collected.


2. HARDWARE-SPECIFIC BEHAVIOR

Determine dependencies involving:

- display hardware;
- keyboard behavior;
- storage controllers;
- serial devices;
- printers;
- memory configuration;
- peripheral interfaces.


3. CP/M VERSUS HARDWARE BOUNDARY

Determine:

- which behaviors are required for CP/M compatibility;
- which behaviors belong to a hardware profile;
- which behaviors are optional capabilities.


4. SOFTWARE IMPACT

Determine:

- whether software depends on specific hardware behavior;
- whether those dependencies are widespread;
- whether profile support affects conformance claims.


5. BIOS PROFILE VALIDATION

Determine:

- whether BIOS behavior can represent hardware differences;
- which BIOS characteristics are externally observable;
- which differences affect software compatibility.


6. PROFILE CONFORMANCE

Determine:

- evidence required for a hardware profile claim;
- tests required for profile validation;
- relationship between generic conformance and profile conformance.


7. EXPERIMENTAL REQUIREMENTS

Create hardware profile validation records.

Each record must include:

- hardware profile;
- software tested;
- environment;
- procedure;
- observed behavior;
- compatibility conclusion.


8. CONTROLLED TEST MATRIX

Include:

- generic CP/M tests;
- hardware profile tests;
- peripheral tests;
- software compatibility tests;
- boundary cases.
