Investigation 062 — CP/M 2.2 Compatibility Conformance Pilot Execution Prompt

Continue the BetterCP/M CP/M 2.2 compatibility investigation series.

Create Investigation 062 as a new evidence report with its own directory
and preserved experimental artifacts.

Do not modify the Compatibility Ledger.

Do not modify previous investigation reports or artifacts.

This is an evidence investigation only.

Do not implement BetterCP/M changes.


OBJECTIVE

Execute a pilot version of the CP/M 2.2 compatibility conformance
process established by previous investigations.

Previous investigations established:

- the CP/M 2.2 compatibility standard;
- compatibility requirements;
- validation categories;
- regression test concepts;
- conformance requirements;
- cross-implementation comparison methodology.

Investigation 062 determines whether the proposed conformance process
is sufficient to evaluate a CP/M-compatible implementation.

Determine:

- whether the conformance methodology is practical;
- whether tests adequately validate compatibility requirements;
- whether evidence collection is sufficient;
- whether additional conformance requirements are needed.


COMPATIBILITY STANDARD

Consider:

- documented CP/M 2.2 behavior;
- Digital Research implementation behavior;
- common CP/M programming practices;
- historically significant software dependencies.

The objective is to validate the conformance process.

Do not implement BetterCP/M changes.

INVESTIGATION QUESTIONS


1. CONFORMANCE PILOT ENVIRONMENT

Identify:

- implementations tested;
- test environment;
- software corpus used;
- available evidence.


2. TEST EXECUTION

Determine:

- which conformance tests were executed;
- whether procedures are reproducible;
- whether expected results are clear.


3. REQUIREMENT TRACEABILITY

Determine:

- whether tests map clearly to Compatibility Ledger entries;
- whether requirements have adequate validation coverage;
- whether any requirements lack meaningful tests.


4. PASS/FAIL CRITERIA

Determine:

- whether results can be classified objectively;
- whether exceptions are adequately represented;
- whether implementation variation is handled correctly.


5. EVIDENCE COLLECTION

Determine:

- whether transcripts, artifacts, and hashes are sufficient;
- whether results can be independently reviewed;
- whether evidence preservation needs improvement.


6. SOFTWARE CORPUS VALIDATION

Determine:

- whether historical software testing contributes useful conformance
  evidence;
- whether additional software categories are required.


7. EXPERIMENTAL REQUIREMENTS

Create conformance pilot records.

Each record must include:

- test identifier;
- compatibility requirement;
- environment;
- procedure;
- observed result;
- pass/fail classification;
- evidence artifacts.
