considered part of the practical compatibility contract.

- documented CP/M interfaces;
- Digital Research implementation behavior;
- utility compatibility;
- development tool compatibility;

- hardware compatibility boundaries;
- software corpus validation.

Investigation 054 examines undocumented behavior discovered during the
compatibility investigation process.

Determine:

- which undocumented behaviors have sufficient evidence to become
  compatibility requirements;
- which behaviors are historical implementation details;
- which behaviors should remain unspecified.

INVESTIGATION QUESTIONS


1. UNDOCUMENTED BEHAVIOR INVENTORY

Identify undocumented behaviors discovered through:

- source analysis;
- software testing;
- reference implementation testing;
- ecosystem analysis.


2. EVIDENCE REVIEW

For each behavior determine:

- source of evidence;
- frequency of occurrence;
- software dependency;
- compatibility impact.


3. SOFTWARE DEPENDENCY

Determine:

- whether existing software depends on the behavior;
- whether the dependency is widespread;
- whether the behavior is observable.


4. COMPATIBILITY CLASSIFICATION

Classify each behavior as:

- required compatibility behavior;
- policy pending;
- not required;
- not guaranteed.


5. IMPLEMENTATION VERSUS CONTRACT

Determine:

- whether the behavior is part of the CP/M compatibility contract;
- whether it is merely an implementation characteristic;
- whether it should be documented as an exception.


6. EXPERIMENTAL REQUIREMENTS

Create validation tests for undocumented behaviors requiring further
evidence.

Each test must include:

- behavior tested;
- purpose;
- procedure;
- observed behavior;
- compatibility conclusion.


7. CONTROLLED TEST MATRIX

Include:

- documented behavior;
- undocumented behavior;
- common behavior;
- rare behavior;
- boundary cases.
