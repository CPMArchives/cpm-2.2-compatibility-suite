OBJECTIVE

Determine the practical CP/M 2.2 compatibility standard required for
compatibility with the historical CP/M community software ecosystem.

Previous investigations established:

- documented CP/M behavior;
- Digital Research implementation behavior;
- utility compatibility;
- development tool compatibility;
- application compatibility;
- communications compatibility;
- hardware compatibility boundaries;
- regression testing requirements;
- software corpus validation;
- undocumented behavior classification.

Investigation 055 consolidates those findings into a practical
compatibility standard.

Determine:

- which behaviors define practical CP/M 2.2 compatibility;
- which behaviors are optional or policy-dependent;
- which behaviors should not be required;
- what conformance categories should exist.


COMPATIBILITY STANDARD

Consider:

- documented CP/M 2.2 behavior;
- Digital Research implementation behavior;
- common CP/M programming practices;
- historically significant software dependencies.

INVESTIGATION QUESTIONS


1. COMPATIBILITY REQUIREMENT CONSOLIDATION

Determine:

- which Compatibility Ledger entries define the CP/M 2.2 contract;
- which requirements are fundamental;
- which requirements are ecosystem-driven.


2. CONFORMANCE CATEGORIES

Define possible classifications:

- required compatibility;
- optional compatibility;
- hardware-profile compatibility;
- unsupported behavior.

Determine the evidence supporting each category.


3. SOFTWARE ECOSYSTEM COMPATIBILITY

Determine:

- whether the current compatibility model explains observed software
  behavior;
- whether important software categories remain uncovered.


4. DOCUMENTED VERSUS PRACTICAL STANDARD

Determine:

- where documented behavior is sufficient;
- where Digital Research behavior matters;
- where community practice establishes expectations.


5. UNDOCUMENTED BEHAVIOR POLICY

Determine:

- which undocumented behaviors should be preserved;
- which should remain unspecified;
- which should be excluded.


6. VALIDATION REQUIREMENTS

Determine:

- how compatibility claims map to regression tests;
- what evidence is required for conformance claims.


7. EXPERIMENTAL REQUIREMENTS

Create a compatibility standard review.

Each conclusion must include:

- requirement;
- evidence source;
- compatibility classification;
- validation method.
