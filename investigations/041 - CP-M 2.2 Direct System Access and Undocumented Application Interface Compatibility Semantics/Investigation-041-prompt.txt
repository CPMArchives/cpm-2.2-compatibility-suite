OBJECTIVE

Determine the CP/M 2.2 direct system access compatibility contract.

Previous investigations established:

-   documented BDOS behavior;
-   BIOS runtime behavior;
-   disk structure behavior;
-   character-device behavior;
-   storage compatibility boundaries.

Investigation 041 determines the compatibility implications of CP/M
software accessing system interfaces directly rather than exclusively
through documented high-level services.

Investigate:

-   direct BDOS access;
-   direct BIOS access;
-   zero-page usage;
-   system vectors;
-   fixed memory locations;
-   undocumented but historically significant interfaces.

Determine:

-   which direct-access behaviors are compatibility requirements;
-   which behaviors are implementation-specific;
-   which historical conventions must be preserved for CP/M software
    compatibility.

COMPATIBILITY STANDARD

Consider:

-   documented CP/M 2.2 behavior;
-   Digital Research implementation behavior;
-   common CP/M programming practices;
-   historically significant software dependencies.

INVESTIGATION QUESTIONS

1.  DIRECT BDOS ACCESS

Determine:

-   how applications locate BDOS;
-   whether applications call BDOS directly;
-   what calling conventions are assumed;
-   what software depends upon these behaviors.

2.  DIRECT BIOS ACCESS

Determine:

-   how applications locate BIOS;
-   how applications invoke BIOS services;
-   which BIOS behaviors are externally visible;
-   what software depends upon these behaviors.

3.  ZERO-PAGE COMPATIBILITY

Determine:

-   which zero-page locations are software-visible;
-   which locations have historical significance;
-   which values or structures applications depend upon.

4.  SYSTEM VECTOR COMPATIBILITY

Determine:

-   which vectors are compatibility-visible;
-   how software uses them;
-   whether they are expected to remain stable.

5.  FIXED MEMORY ASSUMPTIONS

Determine:

-   whether applications depend upon fixed addresses;
-   whether common software assumes specific memory layouts;
-   whether such assumptions are historically significant.

6.  SOFTWARE ECOSYSTEM USAGE

Investigate software categories:

-   system utilities;
-   debuggers;
-   assemblers;
-   disk utilities;
-   development tools.

Determine:

-   common direct-access patterns;
-   undocumented assumptions;
-   de facto compatibility requirements.
