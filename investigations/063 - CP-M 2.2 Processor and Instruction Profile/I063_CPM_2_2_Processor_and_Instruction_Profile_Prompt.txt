Continue the BetterCP/M CP/M 2.2 compatibility investigation series.

Create Investigation 063 as a new evidence report with its own directory
and preserved experimental artifacts.

Do not modify the Compatibility Ledger.

This is an evidence investigation only.

Do not implement BetterCP/M changes.


OBJECTIVE

Determine the processor and instruction-set assumptions that form part
of the CP/M 2.2 compatibility boundary.

Previous investigations established:

- the CP/M 2.2 compatibility standard;
- software ecosystem requirements;
- conformance methodology;
- implementation-independent compatibility boundaries.

Investigation 063 determines which processor-level behaviors are
required for CP/M 2.2 compatibility and which belong to machine or
implementation profiles.

Determine:

- processor assumptions made by CP/M 2.2 software;
- instruction-set requirements;
- CPU-visible behavior that affects compatibility;
- boundaries between CP/M compatibility and hardware profiles.


COMPATIBILITY STANDARD

Consider:

- documented CP/M 2.2 behavior;
- Digital Research implementation behavior;
- common CP/M programming practices;
- historically significant software dependencies.

Distinguish between:

- required processor behavior;
- implementation-specific CPU assumptions;
- optional hardware capabilities.

Do not assume all historical CPU behavior is part of the CP/M contract.

NON-GOALS

INVESTIGATION QUESTIONS


1. PROCESSOR CORPUS

Identify representative CP/M 2.2 software and source materials used
to determine processor assumptions.

Record:

- software name;
- version where available;
- source/archive location;
- processor assumptions;
- evidence collected.


2. INSTRUCTION-SET DEPENDENCIES

Determine:

- which instructions are required;
- whether software assumes Z80-specific instructions;
- whether software assumes 8080 compatibility;
- whether instruction usage affects CP/M compatibility.


3. REGISTER AND FLAG BEHAVIOR

Determine:

- observable register assumptions;
- flag behavior dependencies;
- undocumented CPU-state dependencies;
- software impact.


4. TIMING AND HARDWARE DEPENDENCY

Determine:

- timing assumptions;
- delay-loop dependencies;
- interrupt assumptions;
- whether these belong to CP/M compatibility or hardware profiles.


5. SOFTWARE IMPACT

Determine:

- whether common CP/M software depends on processor-specific behavior;
- whether dependencies are widespread;
- whether they affect conformance.


6. COMPATIBILITY CLASSIFICATION

Classify processor-level behaviors as:

- required compatibility behavior;
- hardware-profile behavior;
- implementation-specific behavior;
- not guaranteed.


7. EXPERIMENTAL REQUIREMENTS

Create processor-profile validation records.

Each record must include:

- behavior tested;
- software tested;
- processor environment;
- procedure;
- observed behavior;
- compatibility conclusion.
