Investigation 061 — CP/M 2.2 Cross-Implementation Differential Validation Prompt

Continue the BetterCP/M CP/M 2.2 compatibility investigation series.

Investigation 060 is complete.

The Compatibility Ledger incorporates findings through Investigation 060.

Create Investigation 061 as a new evidence report with its own directory
and preserved experimental artifacts.

Do not modify the Compatibility Ledger.

Do not modify previous investigation reports or artifacts.

This is an evidence investigation only.

Do not implement BetterCP/M changes.


OBJECTIVE

Perform cross-implementation differential validation to determine which
CP/M 2.2 behaviors represent portable compatibility requirements and
which behaviors are specific to particular Digital Research or other
historical implementations.

Previous investigations established:

- documented CP/M 2.2 behavior;
- Digital Research implementation behavior;
- practical community compatibility expectations;
- software ecosystem dependencies;
- compatibility boundaries;
- conformance requirements.

Investigation 061 validates the compatibility model by comparing
behavior across multiple CP/M-compatible implementations.

Determine:

- which behaviors are consistently reproduced;
- which behaviors vary between implementations;
- which variations affect software compatibility;
- which behaviors belong in the compatibility contract.


COMPATIBILITY STANDARD

Consider:

- documented CP/M 2.2 behavior;
- Digital Research implementation behavior;
- common CP/M programming practices;
- historically significant software dependencies.

Distinguish between:

- portable CP/M compatibility requirements;
- implementation-specific behavior;
- hardware-specific behavior;
- incidental behavior.

Do not assume Digital Research behavior alone defines every required
compatibility behavior.

SCOPE

Investigate:

- multiple CP/M-compatible implementations;
- behavioral differences;
- compatibility significance;
- software-visible effects;
- specification implications.


NON-GOALS

Do not investigate:

- BetterCP/M implementation;
- selecting a preferred CP/M implementation;
- architecture design;
- unsupported operating systems.


INVESTIGATION QUESTIONS


1. IMPLEMENTATION SELECTION

Identify representative implementations for comparison.

Record:

- implementation name;
- version;
- source/archive location;
- platform;
- evidence available.


2. BEHAVIOR DIFFERENTIALS

Determine differences involving:

- CCP behavior;
- BDOS behavior;
- BIOS-visible behavior;
- file-system semantics;
- error handling;
- program execution;
- memory-visible state.


3. COMPATIBILITY SIGNIFICANCE

For each difference determine:

- whether software can observe it;
- whether historical software depends on it;
- whether it belongs in the compatibility contract;
- whether it should remain implementation-specific.


4. SOFTWARE VALIDATION

Determine:

- whether representative software behaves consistently across
  implementations;
- whether observed differences affect compatibility.


5. DOCUMENTED VERSUS IMPLEMENTED BEHAVIOR

Determine:

- whether documented behavior is consistently implemented;
- whether implementation differences reveal hidden compatibility
  assumptions.


6. SPECIFICATION IMPACT

Determine:

- whether current Compatibility Ledger entries remain valid;
- whether requirements should be revised;
- whether additional investigations are required.


7. EXPERIMENTAL REQUIREMENTS

Create differential validation records.

Each record must include:

- behavior tested;
- implementations compared;
- procedure;
- observed differences;
- software impact;
- compatibility conclusion.
