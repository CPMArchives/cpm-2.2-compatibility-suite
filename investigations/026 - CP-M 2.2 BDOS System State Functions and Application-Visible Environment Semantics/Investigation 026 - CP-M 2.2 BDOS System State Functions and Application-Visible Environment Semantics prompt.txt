OBJECTIVE

Establish the application-visible CP/M 2.2 BDOS system-state contract.

Previous investigations have characterized:

- CCP command processing;
- transient entry;
- termination;
- file operation success and failure;
- allocation vectors;
- disk parameter blocks;
- BIOS interfaces.

Investigation 026 determines how applications observe and manipulate
global CP/M environment state through BDOS functions.

The goal is to define:

- what state BDOS owns;
- what state BIOS owns;
- what state survives calls;
- what state survives termination;
- what applications may rely upon;
- what is implementation-specific.

KEY QUESTIONS


1. CURRENT DRIVE STATE

Determine:

- how Function 25 reports current drive;
- how Function 14 changes current drive;
- whether invalid selections return or terminate;
- relationship between BDOS and BIOS drive state.


2. USER AREA STATE

Determine:

- Function 32 behavior;
- current user representation;
- persistence after termination;
- relationship with CCP prompt state.


3. DMA STATE

Determine:

- exact semantics of Function 26;
- whether DMA is simply a pointer or has additional state;
- persistence across BDOS calls;
- persistence across termination mechanisms.

Cross-check I024.


4. ALLOCATION VECTOR EXPOSURE

Determine:

- Function 27 return semantics;
- whether pointer changes with drive selection;
- relationship with Function 31 and DPB.

Do not duplicate I017 allocation mapping work.


5. DISK PARAMETER BLOCK EXPOSURE

Determine:

- Function 31 result;
- DPB ownership;
- whether applications may modify returned data;
- whether DPBs differ between drives.


6. DRIVE RESET SEMANTICS

Determine Function 37 behavior:

- affected drives;
- login state;
- read-only state;
- current drive effects;
- ALV/DPB effects.

Cross-check I017.


7. WRITE PROTECTION

Determine:

- Function 28/40 behavior;
- whether protection is BDOS state or BIOS policy;
- persistence;
- visible effects on later operations.

Cross-check I014 and I025.
