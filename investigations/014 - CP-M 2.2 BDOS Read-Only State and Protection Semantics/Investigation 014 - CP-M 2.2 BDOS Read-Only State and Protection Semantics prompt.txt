# Investigation 014: CP/M 2.2 BDOS Read-Only State and Protection Semantics (Revised)

## Objective

Complete Investigation 014 into CP/M 2.2 BDOS read-only handling and write protection behavior.

Initial source review has identified an important implementation issue:

Protected writes, deletes, and renames may enter DRI's fatal BDOS error handler rather than returning normally through the BDOS call interface.

Do not assume that protected operations return a BDOS error code.

This investigation must determine the observable CP/M 2.2 compatibility behavior of:

- file read-only attributes;
- disk software write protection;
- BDOS read-only vectors;
- protected file operations;
- fatal BDOS error handling paths.

This follows:

- Investigation 008: FCB/Open/Close lifecycle
- Investigation 009: Directory search and DMA semantics
- Investigation 010: Sequential read
- Investigation 011: Sequential write/make
- Investigation 012: Delete/rename
- Investigation 013: Random access/file size

---

# Scope

Investigate:

- BDOS Function 30 — Set File Attributes
- BDOS Function 28 — Write Protect Disk
- BDOS Function 29 — Get Read-Only Vector
- File read-only attribute handling
- Disk read-only state
- Protected operation behavior

Protected operations to test:

- Write Sequential
- Write Random
- Delete File
- Rename File
- Close File after attempted modification

Do not assume any operation returns normally.

# Protected Operation Behavior

## IMPORTANT

Each protected operation must be tested independently.

Do not run multiple fatal-path tests in a single boot session.

Use a reboot/reset harness.

Each test case should:

1. Boot clean CP/M image.
2. Establish the required protection state.
3. Perform exactly one protected operation.
4. Capture:

   - normal BDOS return;
   - warm boot;
   - fatal error handler entry;
   - console output;
   - disk image changes.

5. Reboot before the next test.
