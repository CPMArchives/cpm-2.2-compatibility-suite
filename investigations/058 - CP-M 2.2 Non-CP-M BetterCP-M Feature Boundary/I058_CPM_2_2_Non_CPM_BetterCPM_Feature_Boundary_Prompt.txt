OBJECTIVE

Determine the boundary between required CP/M 2.2 compatibility behavior
and additional BetterCP/M capabilities that can exist without violating
that compatibility contract.

Previous investigations established:

- the CP/M 2.2 compatibility standard;
- compatibility requirement ownership;
- architectural responsibility mapping;
- CP/M personality boundary requirements.

Investigation 058 determines which improvements or extensions can exist
outside the CP/M compatibility boundary.

Determine:

- which features are compatibility-neutral;
- which features require compatibility isolation;
- which features would alter CP/M-visible behavior;
- what constraints apply to extending CP/M.


COMPATIBILITY STANDARD

Consider:

- documented CP/M 2.2 behavior;
- Digital Research implementation behavior;
- common CP/M programming practices;
- historically significant software dependencies.

The objective is to preserve compatibility while identifying extension
boundaries.

Do not design BetterCP/M features.

INVESTIGATION QUESTIONS


1. COMPATIBILITY BOUNDARY

Determine:

- which behaviors are part of the CP/M compatibility contract;
- which behaviors may be extended safely;
- which behaviors must remain unchanged.


2. CP/M-VISIBLE EXTENSIONS

Determine:

- which extensions are visible to CP/M software;
- whether visible extensions affect compatibility;
- what isolation is required.


3. COMPATIBILITY-NEUTRAL FEATURES

Determine:

- which classes of improvements do not alter CP/M semantics;
- what evidence supports that classification.


4. COMPATIBILITY RISKS

Determine:

- which extensions could break existing software;
- which changes require compatibility modes;
- which behaviors must be preserved.


5. PERSONALITY AND EXTENSION SEPARATION

Determine:

- which features belong outside the CP/M personality;
- which features require personality cooperation;
- where boundaries should exist.


6. VALIDATION REQUIREMENTS

Determine:

- how extensions can be validated against the CP/M compatibility suite;
- which tests ensure CP/M behavior remains unchanged.


7. EXPERIMENTAL REQUIREMENTS

Create boundary classifications.

Each classification must include:

- feature category;
- compatibility impact;
- evidence source;
- isolation requirement;
- validation method.
