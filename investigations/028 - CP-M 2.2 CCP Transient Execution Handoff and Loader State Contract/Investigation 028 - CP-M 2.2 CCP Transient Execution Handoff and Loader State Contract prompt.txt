OBJECTIVE

Define the CP/M 2.2 CCP transient execution handoff contract.

Previous investigations established:

- CCP command parsing and dispatch;
- transient lookup;
- COM loading;
- entry environment;
- termination behavior;
- BDOS calling convention.

Investigation 028 examines the boundary between:

    CCP
      |
      v
    transient program
      |
      v
    BDOS

The goal is to determine:

- what CCP prepares before CALL 0100h;
- what state is handed to the transient;
- what state CCP expects back;
- which loader behaviors are compatibility requirements;
- which are DRI implementation details.

KEY QUESTIONS


1. TRANSIENT LOAD SEQUENCE

Determine:

- order of:
    - command recognition;
    - file open;
    - memory preparation;
    - COM loading;
    - page-zero setup;
    - CALL 0100h.

Determine which ordering is externally visible.


2. MEMORY PREPARATION

Determine:

- whether CCP clears the transient area;
- whether unused COM space is preserved;
- whether stack area is initialized;
- whether memory above loaded COM is defined.

Classify application-visible guarantees.


3. PAGE-ZERO HANDOFF

Determine:

- when page zero is prepared;
- which fields are guaranteed;
- whether CCP prepares all fields before loading;
- whether transient execution can modify them before use.

Cross-check I023.


4. DEFAULT FCB TIMING

Determine:

- when FCB1/FCB2 are created;
- whether they are prepared before or after command tail copying;
- whether transient modifications affect CCP return.

Cross-check I023.


5. DMA PREPARATION

Determine:

- DMA state immediately before CALL 0100h;
- relationship between command tail at 0080h and DMA;
- whether DMA restoration occurs before every transient.

Cross-check I022/I023/I024.


6. BDOS AVAILABILITY

Determine:

At CALL 0100h:

- is BDOS fully initialized;
- are BDOS state variables valid;
- can the transient immediately call BDOS.

Cross-check I027.


7. CCP RETURN ASSUMPTIONS

Determine:

After RET:

- what CCP expects;
- what state CCP reads;
- what state CCP reconstructs.

Cross-check I024.


8. TRANSIENT MEMORY LIMITS

Determine:

- how CCP determines available transient memory;
- whether COM files can detect the boundary;
- relationship with BDOS vector at 0005h.

Cross-check I027.


9. ERROR PATHS

Determine:

- missing COM file;
- failed open;
- oversized COM file;
- invalid load conditions.

Determine:

- returned to CCP;
- diagnostic path;
- state cleanup.


10. DRI SOURCE ANALYSIS

Review CCP source for:

- load routine;
- preparation order;
- CALL 0100h;
- return path.

Extract compatibility-relevant behavior only.

FINAL GOAL

Define the CP/M 2.2 CCP-to-transient execution boundary:

When CCP launches a transient program,
what environment must exist,
what state must be prepared,
and what assumptions may the transient safely make?

without requiring BetterCP/M to reproduce DRI-private CCP implementation details.
